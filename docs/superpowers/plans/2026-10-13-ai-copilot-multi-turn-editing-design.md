# AI Copilot Multi-turn Editing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline execution, or superpowers:subagent-driven-development only if the user selects delegation. Steps use checkbox syntax for tracking.

**Goal:** Support validated incremental editing across applied page drafts with the existing proposal workflow.

**Architecture:** The server tool executor owns a request-local working draft. Structured operations produce an immutable candidate, shared validators accept it atomically, and the existing response carries a full PageSchema proposal to the builder. Each subsequent request starts from the current editor snapshot.

**Tech Stack:** TypeScript, Node.js, React, Zustand, pnpm, Vitest, Testing Library; no new runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-13-ai-copilot-multi-turn-editing.md`

## Global Constraints

- Schema version remains 1; page ID and title are preserved during incremental changes.
- No cross-request conversation history or server session persistence in this version.
- The model cannot supply an added component ID.
- Missing insertion anchors and missing update/remove targets are errors.
- Updates shallow merge configurable patches without reapplying defaults.
- Failing batches leave the working draft unchanged.
- `ProductList.products` is preserved but cannot be changed through model patches.
- Retain Apply / Discard and existing revision, page ID, and schema version checks.
- Retain the existing eight-iteration limit and no-proposal result on exhaustion.
- No new runtime dependencies, repository persistence changes, preview/diff subsystem, or automatic publishing.
- One coherent feature delivery; task boundaries do not imply separate PRs or automatic commits.

## Review Focus

- A later operation fails after an earlier one succeeds: no partial candidate enters the working draft (Task 2/3).
- A new request follows a discarded or pending proposal: only the editor snapshot is sent (Task 5).
- A component contains nonconfigurable default data: preserve it and reject model edits to it (Task 1/2).
- A later tool uses an ID generated by an earlier tool: observations and `get_current_page` expose the accepted working draft (Task 3/4).
- Multiple components share a type: Agent is instructed to clarify when no exact target is inferable (Task 4).

## Task 1: Extract Shared Validation Without Changing Generation Behavior

**Files:** Create `apps/agent-server/src/validator.ts` and `validator.test.ts`; modify `tools.ts` and `tools.test.ts`.

**Interfaces:**

```ts
validateProps(componentType: string, props: unknown,
  catalog: AgentComponentDefinition[]): string[];
validateComponent(component: unknown,
  catalog: AgentComponentDefinition[]): string[];
validatePageSchema(page: unknown,
  catalog: AgentComponentDefinition[]): string[];
```

`validateProps` validates configurable patches; full-component validation permits default-only data. These functions collect errors and never modify input or merge defaults.

## Task 2: Define Changes and Implement Atomic Mutations

**Files:** Create `packages/schema/src/page-change.ts`, `apps/agent-server/src/mutations.ts`, and `mutations.test.ts`; modify `packages/schema/src/index.ts`.

**Interfaces:**

Export `PageChange`, `UpdateComponentChange`, `AddComponentChange`, and `RemoveComponentChange` exactly as the spec wire format. Mutation functions consume the validators from Task 1.

```ts
type MutationResult =
  | { success: true; page: PageSchema }
  | { success: false; errors: string[] };

applyPageChanges(currentPage: PageSchema, changes: unknown,
  catalog: AgentComponentDefinition[],
  createId?: (type: string) => string): MutationResult;
```

An optional ID factory makes ID collisions testable. Default implementation uses type prefix plus UUID. Reject an ID collision without committing a candidate; do not introduce an unbounded retry.

- [x] Add success tests: Coupon amount changes 20 → 50 while title/threshold/ID/type stay equal; add merges defaults; remove affects only the exact ID; ProductList title updates preserve products.
- [x] Add insertion tests: before first, before a middle component, append by default, missing anchor rejection, and generated-ID collision rejection.
- [x] Add rejection tests: empty batch/patch, malformed operations, unexpected fields, wrong field types, missing targets, repeated removal, and attempted products edits.
- [x] Add atomicity tests: update amount then remove a missing ID returns failure; source page is deeply equal to its original and a later valid retry produces amount 50. Sequential update/remove and add-before-remove operate in array order.
- [x] Run `pnpm --filter agent-server test -- src/mutations.test.ts` and confirm failures.
- [x] Implement exported types, runtime operation parsing, and immutable candidate mutation. Validate the source envelope and resulting page. Return indexed errors; never mutate catalog defaults or input schemas. Defaults are merged only for add.
- [x] Run `pnpm --filter agent-server test -- src/mutations.test.ts` and `pnpm --filter @mpp/schema typecheck`; both pass.

## Task 3: Integrate the Working Draft and Tool Contract

**Files:** Modify `packages/schema/src/agent.ts`, `apps/agent-server/src/tools.ts`, `provider.ts`, `tools.test.ts`, and `provider.test.ts`.

**Interfaces:** Add `apply_page_changes` to `agentToolNames`. Keep `AgentRequest`, `AgentResponse`, and `AgentTools.execute` signatures. Consume `applyPageChanges` from Task 2.

Successful mutation observations contain `{ success: true, page: PageSchema }`; return a separate clone as `proposedSchema`. This exposes generated IDs to the model without letting observations mutate executor state. Errors retain `{ success: false, errors: string[] }`.

- [x] Add provider-definition assertions for a required nonempty `changes` array, three discriminated operation branches, and `additionalProperties: false` on each operation and added component object. Props accept arbitrary JSON keys for deterministic runtime checking.
